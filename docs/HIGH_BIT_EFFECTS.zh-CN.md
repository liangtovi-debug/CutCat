# 高位深高斯模糊：明确边界的 RGB16 支持

2026-10-23。本轮保留 schema 27，扩展已有 ProRes 422 HQ / MOV 的 SDR 导出能力。源码和 Qt offscreen 验证不等于 Windows/macOS 原生安装包、实际桌面验收或远程 main 已更新；最终发布状态以对应实测报告为准。

## 竞品复核与本轮选择

本轮重新查看 [Blackmagic Design 官方 DaVinci Resolve Color 页面](https://www.blackmagicdesign.com/products/davinciresolve/color)（2026-10-23）。官方介绍节点式调色、范围广泛的 Resolve FX、效果参数关键帧，以及广色域、HDR 和 32 位图像处理。这是专业系统的工作流范围，不是剪辑猫与 Resolve 采用相同算法或具有同等精度的证据。

剪辑猫当前片段特效目录实际上只有**高斯模糊与暗角**，不是任意插件库。本轮选择补齐其中可验证的一项：让高斯模糊在高位深 RGB 视频上直接运行，而不是仅因已有模糊就强制用户改用 8 位输出。暗角继续阻止高位深导出；本地实际 FFmpeg 的原生 RGB16 暗角链路不能协商成功，不能借助隐式低位深转换宣称已支持。

与 Resolve 的差距仍明确存在：本轮没有效果节点树、效果参数关键帧、完整图形色彩管理、线性光特效、HDR、广色域、ACES/OCIO 或 GPU 实时处理。不声称观感或逐像素等效。下一步应先独立实现并验证保留 RGB16 精度的暗角算子，再考虑扩大效果目录；不应仅解除界面拦截或增加“专业特效”标签。

## 使用与参数含义

1. 在片段特效中使用已有「高斯模糊」，沿用原来的 Sigma 数值，范围为 **0–30 个项目像素**，不是百分比或模糊圆盘的半径。
2. 导出时主动选择「ProRes 422 HQ · 10 位 SDR · MOV」。格式选择器接受模糊，只表示模型组合符合范围，实际 FFmpeg 的精度和行为能力检查仍必须在渲染时通过。
3. 生效中的暗角、其他未经验证的片段特效及动画贴纸包仍明确拒绝。可禁用不支持的项，或自行改选 H.264；不会自动更换格式、删除特效或改写项目。
4. 高斯模糊可以与已有基础字幕、经过验证的静态 PNG 贴纸共用此档位；字幕和贴纸各自的运行时检查与素材验证仍必须通过。
5. 零强度或禁用的合法特效保持精确旁路。多个合法模糊按已有列表顺序应用，不合并、不重排；片段特效模型没有关键帧。本轮没有把贴纸的位置／缩放／不透明度关键帧误当成特效参数关键帧。

默认 H.264 输出与 8 位 H.264 预览保留原有算子、参数与路径。高位深路径直接处理 RGB16，而旧支路包含既有格式协商；不能承诺两者逐像素相同。选择高位深不会提升原有 8 位素材自身的信息量。

## 数值、阶段与精度边界

实际顺序为：源解码／归一化与已有修复、调色 → 已适配并补边的 RGB16 项目画布 → **原生 `gbrp16le` 高斯模糊** → 已有片段几何变换 → BT.709 有限范围转换 → 10 位 YUV 4:2:2 轨道合成 → 支持的贴纸／基础字幕 → ProRes 422 HQ。

高斯模糊仍使用现有 `gblur` 的 Sigma 和 `steps=3` 语义。RGB 三个通道在**编码 Rec.709 RGB 码值空间**处理，不进行线性化，也不是物理光能平均。RGB16 源／调色缓存仍把数值限制于 0–1，不能保留负数、超白或无界浮点头部余量。最终 ProRes 是 10 位，不应把内部 16 位处理说成 16 位交付。

运行时必须对固定合成信号检查原生 RGB16 输入／输出、亚 8 位精度及实际模糊行为，并禁止自动插入转换滤镜。检查过滤器名称、版本号、输出标签或单张观感截图都不够；图像先降为 8 位再扩展成 RGB16 不符合本轮承诺。正式渲染在模糊前后明确约束 RGB16，随后沿用显式高位深色彩转换；关闭自动插入转换的选项用于能力探测，不应将它误称为整个复杂导出图的全局选项。

本地实际测试还发现 FFmpeg 的优化模糊路径在窄 RGB16 画布上可产生错误结果，因此**仅在存在生效高位深模糊的导出中**使用 `-cpuflags 0` 保守标量处理。运行时精度／行为检查采用相同选项，同时覆盖较宽的低位精度／脉冲信号和 2×48、Sigma 30 的窄画布常量。此处理不是增加最小画幅限制，也不会改变 H.264、无模糊或禁用／零值模糊的导出选项；可能使导出变慢，不承诺完整导出的速度或固定倍率。仅在本机合成 1080p、12 帧、Sigma 2／steps 3 的孤立模糊测试中，两种模式各运行三次，默认中位数为 0.272 秒、保守标量为 1.352 秒，约为五倍耗时。这不是完整导出、用户项目或 Windows/macOS 原生平台的速度测量。该全局 CPU 选项也会限制同次 FFmpeg 导出中的其他滤镜／编码器 SIMD，不能把孤立模糊的比值直接当作整体导出比值。

字幕仍按其既有编码 Rec.709 颜色混合；静态 PNG 仍由 Qt 生成 8 位 RGBA 图像层。高位深模糊不改变贴纸自身精度、sRGB 输入转换、ICC 或 alpha 合成语义。具体限制见[字幕](HIGH_BIT_CAPTIONS.zh-CN.md)与[静态贴纸](HIGH_BIT_STICKERS.zh-CN.md)。预览与示波器仍是 8 位代理，不是 10 位监看、显示器校色或 HDR 验收。

## 失败与兼容性

- 不兼容的 FFmpeg、能力检查超时、输出预算超限和取消都会明确终止；不会静默回退到 8 位。
- 无生效模糊时不应增加该项探测负担。禁用或零值不要求机器具备原生模糊能力。
- 源文件保护、输入验证、不可覆盖已有导出、临时文件清理和最终输出验证继续适用。最终必须验证 ProRes/HQ、`yuv422p10le`、Rec.709 及真实解码帧有限范围，不能只凭 MOV 后缀。
- 新功能不增加工程字段，也不修改原始素材、已有特效数值或用户字幕。
