# Offline sticker assets

The editor accepts an explicitly selected local PNG or an explicitly selected
version-1 JSON frame-pack manifest. It never downloads sticker content, discovers
unlisted frames, extracts archives, evaluates code, or loads SVG/GIF/WebP/APNG.
The bundled artwork is generated by this project's own geometric source code.

## Supported PNG scope

- PNG signature and exact `.png` extension (case-insensitive) must agree.
- Only 8-bit RGB and 8-bit RGBA PNGs are supported. Both ordinary and Adam7
  interlaced PNGs can be decoded. Palettes, grayscale, 16-bit images, and APNG are
  rejected rather than silently converted.
- Dimensions must be 1–2048 pixels on each side. Each PNG is at most 4 MiB.
- Frame packs contain 1–120 frames. The sum of the decoded RGBA frame sizes is
  at most 128 MiB; repeated references count again toward the budget.
- Every chunk boundary and checksum is checked. The header, ordering, ending,
  and consecutive pixel chunks are checked; trailing bytes are rejected. The
  compressed pixel stream must expand to exactly the scanline size declared by
  the header. This bounds decompression before Qt decodes the PNG.
- A PNG may have no more than 1,024 chunks. Plain `tEXt` chunks are limited to
  64 KiB each. Supported non-pixel metadata is limited to `sRGB`, `gAMA`, `cHRM`,
  `pHYs`, `tEXt`, `tIME`, `sBIT`, and `bKGD`. Truecolor `tRNS` transparency is also
  supported. Unknown chunks, compressed text/profile metadata (`iCCP`, `zTXt`,
  and `iTXt`), and HDR/wide-gamut metadata are rejected.
- Untagged PNGs are assumed to contain display-referred sRGB SDR values. An
  explicit `gAMA` must be 45455 and `cHRM` must contain the standard sRGB
  chromaticities. These checks reject unsupported declarations; they do not
  perform a color conversion. There is no ICC, OCIO, HDR, or wide-gamut sticker
  color-management path, and no claim of linear-light alpha compositing.
- Qt's PNG decoder verifies actual decodability from bounded bytes. Validation
  passes only rendering-critical chunks to that decoder, so metadata is not
  interpreted during validation. The render frame reader also returns validated
  bounded bytes for explicit PNG decoding instead of opening a mutable filename
  through an auto-detecting image plugin. Renderers compare those exact bytes
  with the immutable per-frame hashes before using them.

If an image is rejected for format/profile reasons, re-save a plain 8-bit sRGB
RGB/RGBA PNG in a trusted local image editor. The app does not upload or convert
assets through an online service.

## Export-profile boundary

H.264 8-bit delivery and preview keep the existing static-PNG and frame-pack
pipeline. ProRes 422 HQ 10-bit SDR now accepts verified static PNG assets only;
JSON frame-pack manifests remain unsupported, including single-frame manifests.
Gaussian blur is supported by a separate native RGB16 capability check; active
vignette and unverified clip effects remain outside that high-bit delivery path.
See [high-bit effect boundaries](HIGH_BIT_EFFECTS.zh-CN.md). Disabled
stickers and disabled/zero-strength effects retain their bypass behavior.

Qt still rasterizes sticker artwork, opacity, overlap and transform keyframes
into an 8-bit RGBA asset layer. A capability-probed native FFmpeg overlay blends
that layer into 10-bit video without sending the background through the old
8-bit compositor. This retains the legacy gamma-coded SDR numeric appearance;
it is not linear-light blending, sRGB-to-Rec.709 transfer conversion, ICC/HDR
color management, or a float-through-composition master. The PNG metadata rules
above restrict accepted declarations; they are not proof of color normalization.
Failed 10-bit overlay capability checks block the export clearly, with no silent
fallback. See [full high-bit sticker scope and acceptance](HIGH_BIT_STICKERS.zh-CN.md).

## Version-1 frame-pack format

Select the JSON file itself. The following four fields are required; unknown or
duplicate fields are rejected. The manifest must be UTF-8 JSON and at most
64 KiB. Booleans are not accepted in place of integers.

```json
{
  "version": 1,
  "frames": ["frame_00.png", "frame_01.png", "frame_02.png"],
  "frame_duration": 3,
  "loop": true
}
```

`frames` is the explicit playback order. Every frame must have the same width
and height. A filename can use contained subdirectories with forward slashes,
such as `frames/frame_00.png`. URLs, absolute paths, Windows drive paths,
backslashes, empty components, `.`/`..` traversal, and alternate data-stream
syntax are rejected. A filename is limited to 1,024 characters.

`frame_duration` is an integer from 1 to 300 **project frames**, not milliseconds.
An eight-frame pack with `frame_duration: 3` has a 24-project-frame cycle. The
renderer follows the project frame rate, including rational rates. `loop` is a
JSON boolean. Static PNG assets are represented by one frame, duration 1, and
`loop: true`; overlay placement and duration are separate project settings.

## Local path and integrity rules

The directory containing the explicitly selected input is resolved once as the
canonical trust anchor. This permits ordinary system aliases such as macOS
`/tmp` and `/var`, or a deliberately selected folder alias. The selected PNG or
JSON file itself must not be a symlink or a Windows reparse point/junction.
After canonicalizing the selected directory, every manifest descendant and its
directory ancestry is checked for symlinks/reparse points. A frame may never
escape its canonical pack directory. Only regular files are accepted; device
files and named pipes are rejected. URL/UNC selection is rejected before access.

Bounded reads compare identity and metadata before opening, after reading, and
against the current path. POSIX opens additionally walk directories using
no-follow descriptors. These checks are not a cross-platform file lock. A
render uses validated bytes and rechecks input identity before publishing its
result; external edits must be caught and rejected rather than silently reused.

The immutable `StickerAsset` contains width, height, absolute ordered frame
paths, frame duration, looping, a SHA-256 digest, and ordered per-frame SHA-256 hashes. The digest hashes a canonical
JSON identity containing the schema, asset kind, dimensions, parsed timing and
loop settings, ordered relative manifest filenames, and each PNG's full-byte
SHA-256. Thus:

- Changing pixel bytes, metadata bytes, frame order, timing, looping, or a
  manifest filename changes the digest.
- Reformatting the same JSON or moving the whole pack does not change it.
- A renamed static PNG retains its digest if its bytes are unchanged.
- Imported project overlays store their selected asset path and digest
  separately. `verify_sticker` validates the complete inputs again and rejects
  changed content; a filesystem timestamp alone never establishes integrity.

Imported files remain external project dependencies. Keep the selected PNG or
manifest and its listed frames available; copying only a project file does not
embed its images. A changed asset must be deliberately re-imported.

## Public API

All functions live in `lumen.sticker_assets`:

- `load_sticker(path, cancel=None) -> StickerAsset`
- `verify_sticker(path, expected_digest, cancel=None) -> StickerAsset`
- `read_sticker_frame(path, cancel=None) -> bytes`: accepts an absolute frame
  path returned by validation, validates it again, and returns bounded PNG bytes.
  It does not resolve newly introduced directory aliases.
- `sticker_input_paths(path, cancel=None) -> tuple[Path, ...]`: dependency-only
  validation for project-save overwrite protection. Returns the selected JSON
  followed by ordered frames, or one static PNG. Does not import Qt or decode
  PNGs. Missing/invalid inputs raise an error for the caller to handle safely.
- `builtin_stickers() -> tuple[tuple[str, Path], ...]`: UI labels and the three
  package-local original asset paths.

`StickerAsset` is a frozen dataclass with immutable frame tuples. Invalid,
unsupported, missing, or changed inputs raise `StickerAssetError` (a `ValueError`).
`cancel` accepts a `threading.Event`; cancellation raises `StickerCancelled`, a
subclass of `StickerAssetError`. Validation checks it during bounded reads,
manifest traversal, chunk checking, inflation, and between image decodes. A
single native decode is bounded by the supported image size, but is not forcibly
interrupted halfway through a Qt call.

## Bundled original artwork and reproducibility

Package data under `lumen/assets/stickers/` contains:

- Spark star: transparent 256×256 static PNG, original gold star geometry
- Check bubble: transparent 256×256 static PNG, original check/speech-bubble geometry
- Pulse ring: eight distinct transparent 256×256 PNGs and a looping manifest,
  three project frames per animation frame

Regenerate the artwork offline using the pinned project environment:

```sh
python scripts/create_original_stickers.py
```

Use `--output /path/to/new/folder` to generate a separate copy. The generator
uses only QImage/QPainter circles, polygons, paths, and rounded rectangles; it
uses no fonts, third-party imagery, downloads, model-generated images, or Pillow.
Reproducibility compares exact premultiplied RGBA artwork and animation
semantics under the pinned PySide6/Qt environment, without a numeric tolerance.
Separate tests pin every shipped PNG/manifest byte hash and the asset identities
stored in projects. Straight-RGB PNG codes and compression bytes need not be
identical across regenerations; [the measured rounding investigation](STICKER_REPRODUCIBILITY.md)
explains the distinction. Keep the shipped assets unchanged when validating a
new platform: generate into a separate `--output` directory. Native
Windows/macOS regeneration has not yet been validated.

`lumen/assets/stickers/LICENSE.txt` records original-asset provenance and
references the repository root [LICENSE](../LICENSE). These original assets
are covered by the CutCat Use, Modification and No-Sale License; this is not
a public-domain dedication. No third-party artwork-license obligations are
introduced. Qt/PySide6 remain separately licensed software dependencies.

## Verification

Run `python -m pytest tests/test_sticker_assets.py -q`. The focused tests cover
semantic/full-byte tampering, JSON ambiguity, traversal and symlinks, format and
color restrictions, dimensions, exact 128 MiB decoded budget, excessive chunks,
metadata limits, corruption, bounded inflation, cancellation, immutable results,
reproducible generated assets, transparency, and distinct animation frames.
