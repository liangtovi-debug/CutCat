# 编码前真峰值估算：有限范围诊断

本轮在最终立体声混音分析中补充每声道真峰值估算（dBTP）。采样峰值可能漏掉两个采样点之间的波形超限；该诊断帮助使用者在已有片段增益控件中调整后重新分析。不自动修改声音，不新增主输出增益、归一化、限幅器、工程字段或过载事件计数。

## 数学与边界

使用 [ITU-R BS.1770-5 附录 2](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-5-202311-I!!PDF-E.pdf) 印刷页 18–19 的 4 相、每相 12 个系数，48 kHz 输入重建为四倍采样估算。每相输出为 y[p,n] = Σ h[p,k] x[n-k]。系数按原表逐行录入，使用 float64 运算，无需整数实现的 12.04 dB 预衰减和恢复。

输入前后按零延拓，保留 11 帧历史，并在确认实际采样数完全正确后额外处理 11 帧零以清空滤波尾部。零只进入独立估算器，不进入响度测量或导出音频，不增加节目采样数或时长。实现按有限块处理，不保存全节目四倍上采样数组。

显示值明确采用 max（原始采样峰值，FIR 重建峰值）作为采样峰值下界保护，避免有限滤波器响应低估已经存在的原始采样。测试分别验证未加保护的 FIR 峰值和最终保护值，不用保护值掩盖尾部丢失。转换为 20 log10（峰值）；静音显示负无穷，超过满刻度的值不截断到 0 dBTP。

这仍是有限滤波器、四倍采样的估算，不是理想连续时间峰值或经认证仪表。高频、有限节目边界和滤波器响应会影响估算误差。采样过载计数与首次时间仍仅指原始采样，不将真峰值估算转换成事件或精确超限时间。AAC 等后续编码可能改变峰值，不能替代最终编码文件检测或交付合规检查。

## 证明方法

- 独立标量卷积使用原始标准系数，验证首尾及单采样脉冲、滤波边界和任意字节分块；重复完成必须幂等。
- 相位变化且平滑加窗的高频测试证明：原始采样均小于满刻度时，重建波形仍可能超过满刻度。无限正弦解析振幅不能直接当作硬截断有限波形的全局峰值。
- 检查左右不对称、反相、静音、极小浮点值、超过 1 的采样、非有限输入拒绝和线性增益缩放。
- FFmpeg 只作为独立的次级比较，先验证其插值尾部。当前运行时直接启用 ebur128 peak=true 会漏报位于节目最后的脉冲；比较夹具在其独立峰值分支补零，而产品原有 LUFS 分支完全不变。
- 两小时合成流检查固定内存、末尾峰值和取消预算；不写出庞大的音频文件。已有 PCM 精确一致性、响度、来源证明、源变更、后台新鲜度检查和界面过期保护继续回归。

## 本轮与专业付费软件的对比

[Adobe Premiere 官方指南](https://helpx.adobe.com/premiere/desktop/add-audio-effects/apply-audio-effects/apply-loudness-meter-to-a-track.html) 将 Loudness Meter 放在 Audio Track Mixer 的 Mix Track 效果中。剪辑猫本轮只补齐手动触发的最终混音离线真峰值估算；不宣称补齐实时轨道或主输出仪表、轨道混音器、自动化、限幅或编码文件交付认证。

[FFmpeg 官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html#ebur128-1) 描述了通过上采样查找 true peak，且依赖 libswresample。运行时行为必须用真实夹具验证，不能仅靠选项名称认定尾部正确。上述官方资料于 2026-10-25 查阅。

剩余差距包括实时轨道/主输出计量、轨道混音和自动化、受控的主输出电平调整、编码后交付检测及原生 Windows/macOS 验证。当前轮次不新增依赖，不更改 schema 33，不进行远端修改、托管 CI 或 Library 发布。验收以同一冻结源码的完整测试、独立复核和源包新鲜解压复验为准；本文件本身不代表这些验收已经通过。
