# Preserved sticker bytes and artwork reproducibility

## Measured restored-source regression, 2026-10-15

The restored 755-test baseline passed 754 tests and failed the generated-artwork
comparison. No shipped PNG, manifest, project, or project hash was changed during
this investigation. The environment used the pinned PySide6/Qt 6.8.3 and NumPy
2.2.4 on Linux x86-64. This is not a native Windows/macOS validation result.

Regenerating into a separate temporary directory and comparing decoded 256×256
RGBA pixels across all ten frames found:

| Frame | Pixels with a straight-RGB difference | Maximum channel difference |
|---|---:|---:|
| Spark star | 19 | 1 |
| Check bubble | 4 | 1 |
| Pulse ring 00 | 8 | 1 |
| Pulse ring 01 | 4 | 1 |
| Pulse ring 02 | 4 | 1 |
| Pulse ring 03 | 8 | 1 |
| Pulse ring 04 | 8 | 1 |
| Pulse ring 05 | 4 | 1 |
| Pulse ring 06 | 4 | 1 |
| Pulse ring 07 | 8 | 1 |

Exactly 71 of 655,360 pixels differ, always by one code value in one RGB
channel. Every alpha value and every fully opaque pixel is identical. At every
pixel of every frame, converting both PNGs to
`QImage.Format.Format_RGBA8888_Premultiplied` gives **exactly identical bytes**.
The renderer uses Qt's equivalent ARGB32 premultiplied representation.

The first reported mismatch is Spark star byte 84,393: green 213 versus 212.
Both values map back to the same premultiplied color at that pixel's alpha.
Thus the discrepancy is in an equivalent straight-alpha representation, not
in the 8-bit premultiplied artwork used by the compositor. The generator paints
and downsamples a premultiplied QImage before PNG serialization, which needs
straight-alpha colors. This quantized conversion can represent one premultiplied
color by adjacent straight RGB values.

Disabling Qt's reported SIMD feature families for a separate regeneration did
not change the result on this host. The evidence does **not** establish a
specific CPU instruction, native encoder build, or operating system as the
original cause. Do not claim that it does.

## Regression contract

- Artwork regeneration uses exact premultiplied RGBA equality, dimensions,
  frame count, order, timing, looping, transparency, and PNG resolution metadata.
  There is no per-pixel tolerance or skipped platform.
- Separate fixed SHA-256 assertions pin the complete bytes of all ten shipped
  PNGs and the frame-pack manifest. These constants are never regenerated by the
  test or copied from freshly generated output.
- Separate fixed asset-identity assertions retain the three semantic digests
  used by saved projects, including the preserved effects and local-AI demos.
- Existing import/render integrity checks continue to verify complete PNG bytes,
  metadata, ordering, timing and every dependency. Premultiplied equality is
  only an artwork-generation test; it does not replace runtime integrity checks.

To validate in another environment without overwriting distributed resources:

```sh
python scripts/create_original_stickers.py --output /path/to/temporary/stickers
QT_QPA_PLATFORM=offscreen python -m pytest tests/test_sticker_assets.py -q
```

For manual diagnosis, load each shipped and regenerated frame with QImage,
convert separately to `Format_RGBA8888` and
`Format_RGBA8888_Premultiplied`, and compare their `constBits()` bytes. Keep
alpha, per-channel maximum and differing-pixel counts separate. If
premultiplied pixels differ, investigate that platform rather than widening a
tolerance or regenerating the shipped files.

Focused verification after this change: **131 sticker tests passed**. Native
platform reproduction and the complete integration suite remain separate gates.
