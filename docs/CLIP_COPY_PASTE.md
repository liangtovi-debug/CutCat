# Private whole-clip Copy / Paste

Current bounded schema39 candidate. This is a local implementation and verification scope, not a remote-main, hosted-CI, native-package or paid-editor-parity claim. Acceptance requires matching frozen-source focused, independent-review, aggregate and fresh-extraction receipts.

## Workflow and exact placement

Select committed timeline clips and choose **Edit → Copy clips**. Whole persistent groups expand according to existing selection rules. Copy checks media/LUT dependencies on a cancellable worker, then stores an immutable parameter snapshot privately in this window and project session. It creates no project edit, Undo entry or preview invalidation and never reads/writes the system clipboard. A failed, canceled or stale Copy retains the last successful copy.

Choose **Edit → Paste clips at playhead (original tracks)**. The dialog initially captures the current playhead. An exact **Paste destination (project frame)** field also permits an explicit append or gap beyond the currently seekable content; it is never an automatically selected free position. **Capture playhead** explicitly replaces that target. Review the scope and choose **Paste clips** to run fresh cancellable dependency checks and commit once.

With `anchor = min(copied.start)`, every new position is:

```
new.start = destination + copied.start - anchor
```

Original tracks and relative gaps remain unchanged. The paste appends independent clips with new IDs, remaps copied groups to new group/clip IDs and gives each copied effect a new ID. It does not merge separate groups or attach clones to originals. All old project records remain exact. One Undo removes all new clips/groups; Redo restores the same IDs. Successful paste selects the new clips and follows the ordinary content-edit preview invalidation path.

Collision, locked destination, negative/out-of-range target or non-equivalent audio sample phase rejects the whole operation. Nothing is overwritten, rippled, trimmed, moved to another track, rounded or relocated to a nearby gap. Reading a locked source is allowed; pasting back onto its locked track is not. This first version explicitly rejects **any copied video-transition endpoint**, including an endpoint brought in by group expansion. It does not silently discard or reconnect transitions.

## Frozen parameters, shared sources

The snapshot preserves each complete `ClipTimeMap` (exact rational source In/Out, speed and partial tail), creative grade **and input encoding**, LUT reference, ordered effects, gain/mute/fades, stabilization/restoration, transform/composite and clip-local motion/window keys. Negative and beyond-duration animation handles remain unchanged, not rebased or clipped. Mutable parameters in originals and clones are independent.

Source media are referenced, not duplicated or transcoded. Generated sound/speech provenance remains on the same Media record; historical source-caption IDs do not authorize copying captions. Captions, stickers, saved source ranges and timeline markers are neither copied nor moved. Existing source clips can be edited or deleted after Copy without changing the frozen parameter values, provided the same referenced media remain in this project. This is not a frozen media backup and does not promise the same final scene after placement over another background.

The clipboard is not saved in the project. New/Open/Recover into another editor session clears it; another window/project cannot use it. A changed project FPS rejects rather than retiming. A normal intervening project edit does **not** invalidate the saved parameter snapshot: a new Paste plan binds the current revision and whole-project signature. A pending verification also binds the current owner/session, target, copy token and new IDs. Cancel, target/playhead changes, replacement Copy, project edits, Undo/Redo, lock changes or project replacement revoke a pending result. Recapturing a stale dialog explicitly creates a fresh plan; no result rebases itself.

## Dependency and resource contract

All filesystem work runs off the GUI thread. The current Media record must still match the copied record, including path, interpretation, timing and provenance; conservative equality also rejects metadata changes such as a rename until a new Copy. Missing/relinked/changed dependencies reject. Ordinary files use the existing three bounded 64 KiB source-identity samples plus device/inode/size/timestamps, with separate portable path-to-path and descriptor-to-descriptor before/after checks. This detects ordinary replacement and metadata-preserving-mtime edits; it is **not** a whole-file cryptographic proof against storage that can rewrite unsampled bytes and every identity field.

Generated audio and all referenced LUTs, including currently bypassed LUTs, use full SHA-256 reads. Generated bytes must additionally match the recorded provenance output hash. Files must be plain local files; symlinks/reparse/special files reject. Dependencies are checked in two passes so an earlier file must still match when the batch completes. A successful receipt is a recent observation, **not a file lock**; an external write after verification remains outside this guarantee.

Bounds per operation: 2,000 clips; 8 MiB serialized parameter snapshot; 128 media/LUT dependencies; 60 seconds; 256 MiB total reserved file reads across both passes; 64 MiB per generated source or LUT. Full-file reads reserve their actual requested chunk size before reading, so growth between stats cannot evade the shared budget. Cancellation/deadlines are checked between bounded reads (a blocking operating-system filesystem call itself cannot be preempted). No media is decoded or copied by these checks. Unlike source cutting, whole-clip translation has **no 30-second selection/proof limit**.

## Exact audio preservation

For every audible clone, the complete existing local audio compiler contract must match: exact source samples, retiming filters, leading silence, output sample budget, gain and globally compiled fades. Only final placement delay may change. Additionally every audible contribution must share exactly:

```
sample_boundary(destination) - sample_boundary(anchor)
```

Both conditions matter at fractional FPS: equal local lengths can still shift different clips by 1,601 versus 1,602 samples. The operation refuses rather than dropping/adding samples, changing the compiler or rounding the destination. Muted/no-audio clips and source intervals that are fully silent both before and after create no audible phase constraint. No rendering/audio algorithm, schema or dependency is changed.

## Keyboard and UI boundaries

Fresh Windows/macOS presets use Ctrl/Cmd+C and Ctrl/Cmd+V. Previously saved shortcut profiles receive both new commands **unbound**, preserving custom assignments. Dispatch remains in the existing event filter, not QAction shortcut bypasses: native text editing, numeric input, IME composition, modal/popup focus, unrelated lists and inactive windows retain their ordinary behavior. Auto-repeat/double-click cannot commit twice. Dialog labels, scope, errors and help are English/Chinese and screen-bounded with scrollable content. Linux offscreen tests do not establish physical Windows/macOS keyboard, IME, accessibility-device or native performance validation.

## Official-editor comparison and next gaps

Checked official Adobe documentation on 2026-10-26. Its [clip Copy/Paste guide](https://helpx.adobe.com/premiere/desktop/edit-projects/change-clip-sequence/copy-and-paste-clips.html) documents selecting one or more clips and placing copies at a chosen playhead location. The [grouping guide](https://helpx.adobe.com/premiere/desktop/edit-projects/change-clip-sequence/group-clips.html) describes managing grouped clips together, including copying, with separate trim and linked-A/V behavior. CutCat now addresses this bounded reuse workflow, not the whole Premiere editing model.

Adobe's [sequence-marker copy option](https://helpx.adobe.com/premiere/desktop/organize-media/apply-labeling/copy-and-paste-sequence-markers.html) separately includes marker information in a copy operation. CutCat deliberately keeps project markers fixed instead of silently inventing that policy. These references establish common workflows, not that the features are exclusively paid.

Remaining gaps include cross-project/window/system-clipboard transfer, Cut, duplicate-by-drag, explicit track remapping, overwrite/insert Paste, attribute-only Paste, transition cloning with source-handle verification, linked A/V ownership and optional annotation-copy policy. Broader proxy, variable-track, mixed-rate/VFR, realtime/GPU and native-release work remain separate. No overall completion percentage is inferred.
