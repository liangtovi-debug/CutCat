# 分数帧率素材尾帧修复

## 本轮修复

- 原逻辑用 `int(容器秒数 × 项目帧率)` 计算可选素材帧数。生成的 24 帧 30000/1001 fps Matroska 文件，其容器时长为 0.800 秒，旧逻辑只允许 23 帧，最后可解码帧无法加入完整片段。
- 新导入视频额外尝试解码尾段，读取真实末帧时间戳及帧持续时间。仅当尾段时间戳与声明平均帧率的恒定帧率网格吻合（允许容器时间基量化误差）时保存有理数末端证据。项目帧数按现有 FFmpeg fps 滤镜的最近 EOF 边界计算，不对所有容器时长直接向上取整。
- 已验证的视频-only素材按相对视频起点的端点计算时长，避免部分 Matroska 非零起始时间被重复计入。带音频素材不会因为画面较短而截掉原有音频范围。
- 保存格式升级至 15。旧工程缺少证据字段时保留旧行为，不悄悄调整已保存片段；重新导入或重连可重新检查。重连同步更新证据，正常保存/重开保留证据。
- 本轮不改动受控 AI 编辑、Agent SDK 接口、API 设置界面、音效库或其授权/来源信息。

## 边界与限制

- 这是尾段证据，不是全片恒定帧率认证。可变帧率素材末尾可能由 FFmpeg 根据相邻时间戳外推；尾段不符合已知网格时不修正，不宣称解决所有 VFR 时长问题。
- 仅请求末尾约两秒，解码器仍可能回到更早的关键帧。额外探测最多等待 10 秒，仅接受不超过 1 MiB 的结果。无法定位、解码报错、缺时间戳/持续时间、非单调帧、超时或过大结果均回退原有算法，不阻断正常导入。
- 此处不修复既有“混合音视频 + 非零起始时间 + 部分容器绝对 duration”问题。例如起点 5 秒、音频长 2 秒的某些 Matroska 文件，旧容器元数据路径仍可能报告 7 秒。没有截短这类素材以免丢音频。
- 损坏素材的完整性与全片解码性能不在本次保证范围。没有在用户电脑操作，没有运行付费模型接口，没有提交远端仓库或执行 Windows/macOS 原生构建。

## 验证方式

本地合成素材，不含用户影像。测试将最后一帧标为白色，从实际源解码建立 oracle，再检查预览、导出、静帧、尾部半速裁切的真实像素及帧数；还检查越界拒绝、保存重开、旧格式、损坏/缺信息/超时回退。

覆盖 30000/1001、24000/1001、60000/1001、25 fps，以及 30/60 fps 混合项目帧率，1/2/7/24/25/61 帧短片、非零起点、可变帧率保守回退、较长音频。最终测试统计在交付说明中记录。

## 最终结果（2026-10-22 UTC）

- 冻结代码整轮回归：3718 通过、2 跳过、0 失败，1172.96 秒（19 分 32 秒）。2 项跳过分别需要显式本地 CJK 字体测试样本和 Windows 原生路径语义；79 条警告为 Qt API 弃用提示。
- 新增尾帧专项：33 通过。修复收尾后的相关媒体、模型、音效来源兼容与中文覆盖集合：141 通过。
- 独立审查阶段：51 项通过。额外 headless Qt 重连检查通过：旧 23 帧片段保留选区，重连后素材可用范围恢复为 24 帧，保存重开保持正确。
- 最终代码、测试和资源在整轮运行期间保持不变；交付压缩包逐文件核对，并检查可正常解压。
- 测试仅使用本地生成素材与本地假模型，不代表真实 API 推理、Windows/macOS 原生构建、远端提交或 CI 成功。
