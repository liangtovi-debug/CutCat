# Joint qualifier: deliberate click-to-replace

Professional → Color → Hue / saturation / luma qualifier → **Replace ranges from source click**. The button switches to the frozen source view. Click a chromatic active-picture sample: the dialog initializes hue ±10 degrees, HSV saturation ±0.10 and encoded Rec.709 Y′ ±0.10 (S and Y′ clipped to their 0–1 parameter domain), then shows the pending matte. Re-arm to replace again. This is not cumulative or additive selection. Existing feathers, correction adjustments and enable state are preserved exactly. Refine the numeric ranges, enable correction if wanted, and Apply. Cancel changes nothing; Apply is one standard undoable grade transaction.

## What is sampled

The same selected-clip snapshot as the existing qualifier: RGB16 decode → input normalization → active-picture spatial restoration → primary and RGB/hue curves → **sample** → qualifier → LUT. Display conversion alone clips/quantizes to RGB8. Classification reads the immutable float32 sample, never the matte, adjusted preview, final composite or proxy. Adjustment changes cannot feed back into sampling. Source/project/playhead changes invalidate the dialog, including immediate validation before sampling and applying.

The initial overview is an exact strided sample grid, longest edge at most 512. Fine objects between overview samples can be missed. **Detail** exposes a contiguous 512, 256, 128 or 64-pixel local crop at stride one, not an enlarged overview. Double-click an overview location to inspect it; use the zoom menu or scroll wheel, middle-drag to pan, and X/Y integer controls to address any fitted-canvas pixel. The last chosen color remains pinned to its source coordinates independently of pan/zoom; the marker is hidden when that exact sample is absent from the view.

Canvas positions are Qt logical coordinates. Painting and picking share one explicit physical-pixel-center lookup across device pixel ratios; each displayed cell maps through the current crop origin and stride to an exact source pixel. The sample label shows this zero-based fitted-source coordinate and original RGB/H/S/Y′ values. The resolution label distinguishes sparse overview from full-resolution local matte calculation. A smaller physical canvas may still display fewer cells than a large crop; select the 64-pixel detail view to inspect individual pixels comfortably. Exports always evaluate the entire frame.

“Full resolution” means the already fitted project-canvas snapshot, not camera sensor pixels before project scaling. A 4K clip in a 1080p project is sampled on that 1080p processing canvas, matching rendering. Navigation reuses the single immutable snapshot and never re-decodes or allocates another full 4K processing buffer. CPU/matte/display work uses at most 512×512 sampled pixels; cancellation/close releases the snapshot and image caches.

Display letterboxing and fitted-source padding cannot initialize a range. The resultant color-range matte can nevertheless include graded source padding, just like the renderer. Non-finite or outside-0–1 RGB is rejected, never clipped into a false sample. Chroma at or below 0.000001 is rejected because hue is undefined/unstable there. The existing numeric full-width hue control can still explicitly include gray. Active stabilization, transparent sources and changing restoration geometry remain unsupported by snapshot capture.

## Range and transaction semantics

H is cyclic hexcone hue, S is HSV saturation, Y′ = 0.2126R′ + 0.7152G′ + 0.0722B′ in encoded Rec.709. S is not HSL saturation; Y′ is neither HSL lightness nor linear luminance. Initial tolerances are CutCat's documented starting choices, not automatic semantic segmentation or Resolve's proprietary settings. The clicked pixel belongs to the core of all three ranges. All three feather weights multiply outside the core.

A single joint interval cannot in general express the union of two separated colors without also selecting unrequested combinations. Therefore there is no misleading “add” button or drag union. Only deliberate replacement is implemented. Sampling does not enable grading, reset adjustments or alter feathers. Pending settings remain local; project schema stays 18 because no persisted field changed. Save/load, recovery and grade-copy use the existing exact settings path.

## Competitor comparison and next boundary

The [current official DaVinci Resolve Color page](https://www.blackmagicdesign.com/products/davinciresolve/color) describes eyedropper clicking/dragging, hue/saturation/luminance selection, key inspection and refinement. The [Resolve 17 Beginner's Guide](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-17-Beginners-Guide.pdf), printed page 316, describes clicking to change the three ranges. The archival [Resolve 11 Reference Manual](https://documents.blackmagicdesign.com/UserManuals/DaVinci_Resolve_11_Reference_Manual.pdf), printed pages 592–593, distinguishes normal sampling, add/subtract range and add/subtract softness. The historical reference is not a claim about the latest manual version.

The [Resolve 20 Colorist Guide](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Colorist-Guide.pdf) describes scroll-wheel viewer zoom and middle-button panning. CutCat now adds exact local-pixel detail navigation to its single-click initialization workflow, not Resolve-equivalent algorithms or a calibrated viewer. Missing: drag/add/subtract sampling, asymmetric feather, matte cleanup, spatial windows/tracking, multiple keys/nodes, HDR/OCIO and calibrated display management. The next meaningful bounded round is a non-destructive key-inspection overlay that makes the selected range visible in context, with original source sampling and explicit display-stage labels. It can help inspect small-target spill without pretending that a single interval can safely represent arbitrary added/subtracted colors. No next-round source changes are made before this artifact is frozen and delivered.

Verification is Linux local-source/offscreen Qt only. No new Windows/macOS installer, native dual-platform build, private GitHub main update or live API use is claimed.
