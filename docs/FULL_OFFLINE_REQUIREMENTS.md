# Windows 与 macOS 全本地视频编辑器需求与技术路线

核查日期：2026 年 10 月 14 日

## 目标与当前状态

目标是覆盖剪映级常用和专业创作能力，所有媒体解码、剪辑、语音识别、字幕、配音、效果与导出均在客户电脑完成。本文是需求与候选技术路线，供项目路线图采用，不是已实现产品说明。

**本文没有检查当前代码或运行当前编辑器，因此所有功能的当前实现状态均为“待代码与实机验收确认”。下列条目是计划需求；列出开源组件不等于已集成、已通过测试或已获完整分发授权。** 本次核查来自官方公开页面和上游文档，未逐菜单实测指定版本剪映，不能称为完整竞品审计。

“全部剪映功能”应转为固定版本、平台和地区的功能矩阵，并逐项记录输入限制、质量标准、性能、离线替代和验收结果。剪映和 CapCut 的功能、授权和上线节奏不能视为完全相同。

## 官方对标依据

- [剪映专业版](https://www.jianying.com/web/professional)明确展示智能字幕、文本朗读、曲线变速、智能抠像和音频、贴纸、花字、特效、滤镜素材库。
- [剪映官网](https://www.jianying.com/)展示蒙版、关键帧、色轮与曲线、浮点调色、多机位、多时间线，以及画质增强、补帧、声音分离、降噪、响度统一、文本剪口播、音色克隆、数字人和素材智能搜索等。
- [CapCut 桌面介绍](https://www.capcut.com/tools/desktop-ai-power)可补充参考自动重构图、场景检测、关键帧曲线、效果与模板，但不能作为剪映相同版本存在同一功能的证明。

## 功能需求清单

以下每组均为计划需求，现有实现状态待确认。P0 表示形成可靠剪辑与语音闭环的优先需求；P1 为实用功能扩展；P2 为需要单独验证硬件、质量或授权的高级能力。优先级不是交付日期承诺。

### 编辑与工程基础

- P0：多视频、音频、字幕轨；分割、修剪、吸附、波纹删除、联动、编组、锁定、静音、隐藏。
- P0：画布尺寸与比例、裁切、旋转、翻转、位置、缩放、透明度、画中画。
- P0：撤销重做、自动保存、崩溃恢复、素材重链接、项目打包迁移、项目版本迁移。
- P1：变速与曲线变速、保持音调、倒放、定格、循环、抽帧。
- P1：关键帧插值和曲线编辑、复合片段与嵌套、多时间线、多机位、波形同步。
- P2：AI 帧插值及更复杂的自动剪辑。

### 自动字幕与文本

- P0：真实本地中文与英文 ASR；选择语言、源轨道、片段范围或完整时间线；任务进度、取消、失败重试。
- P0：可编辑字幕轨；文本修改、分句合并、批量样式、波形校时、SRT 导入导出与烧录。
- P0：转录文本、词或句时间戳、显示样式分开存储；改字不丢时间信息。
- P1：逐词时间戳与高亮、多字幕轨、VTT/ASS、双语字幕、离线翻译、说话人标签、歌词模式。
- P1：查找替换、专有名词词典、数字标点规范化、中英混排、最大行数与阅读速度检查。
- P1：描边、阴影、气泡、花字、进出场动画、字体替代提示、安全区。
- P2：文本驱动剪口播、无效词与停顿建议；删除须可回退且不破坏源媒体。

### 本地字幕朗读与配音

- P0：从字幕或独立文案生成中文、英文配音；选择已授权音色、试听、语速、音量、停顿。
- P0：逐句生成可独立编辑的音频片段；支持重新生成单句，保留文字、模型版本、音色和参数来源。
- P0：可选择按字幕时间摆放或连续自然朗读；显示配音超时、片段重叠和空隙。
- P0：不静默截断尾音。文本无法自然读进给定时长时，提供调速、延长片段或修改文案选项；任意文本的自然度和严格定长不能同时保证。
- P1：多音字、人名、数字、英文缩写发音纠正；背景音乐闪避、响度统一、淡入淡出。
- P2：情绪、方言、更复杂韵律和音色克隆。克隆需有声音权利人授权，不附赠仿冒知名人物音色。

### 视觉效果与包装

- P0/P1：转场、滤镜、可调参数的效果链、参数复制粘贴、预设保存。
- P1：线性、圆形、矩形、文字及钢笔蒙版，羽化、反选、动画。
- P1：色度键、基础稳定、镜头分割、跟踪贴纸或文字、自动重构图。
- P1：静态和动画贴纸；明确 PNG/WebP/GIF/SVG 等支持格式、透明通道和时间基准。
- P1：原创字幕、片头片尾、分屏、商品展示模板；可替换槽位、字体和资产依赖检查。
- P2：人像抠像、手工补边、复杂目标跟踪、美颜美体、时域去噪、修复和超分。
- 每种效果必须有统一的预览与导出语义，不能仅在预览画布看得到。

### 音频编辑

- P0：提取音频、音量、声像、淡化、声道映射和不同采样率处理。
- P1：录音、增益包络、EQ、压缩、限幅、降噪、混响、变调、变声、响度和峰值表。
- P1/P2：人声与伴奏分离、静音检测、节拍标记、音乐自动闪避。
- 所有增强功能保留原始音频，并可比较处理前后；分离残留和失真须可被用户听见并调整。

### 色彩管理与媒体管线

- P0：输入色域和传递函数、工作空间、显示转换、输出色彩标签明确一致；预览与导出一致性测试。
- P1：LUT、色轮、HSL、RGB 曲线、示波器和浮点处理。
- P2：SDR/HDR、10-bit、PQ/HLG、HDR 转 SDR 色调映射分别验收，不能只提供无完整链路的 HDR 开关。
- P0：VFR、长 GOP、旋转元数据、损坏素材、长时间音画同步处理。
- P0：代理、缩略图、波形和帧缓存；缓存路径、容量、失效与清理。
- P1：预渲染、后台任务与磁盘预算。
- [OpenColorIO](https://opencolorio.org/)可用于色彩变换框架；它不能代替完整 HDR 显示和编码实现。

### 导出与兼容

- P0：平台和硬件对应的编解码器/容器矩阵；CPU 回退及可选硬件编解码。
- P0：分辨率、帧率、码率或质量、音频声道、字幕输出、范围导出、取消与错误提示。
- P0：磁盘不足预检、导出后打开验证、画面帧数和音频时长同步检查。
- P1：批量队列、失败重试、导出预设与项目归档。
- P1：[OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO)可评估用于时间线交换，但不代表兼容全部剪映草稿或所有效果。

### 产品质量与可访问性

- P0：Windows/macOS 安装、签名或公证、升级与回滚、显卡兼容、后台计算崩溃隔离。
- P0：快捷键、中文输入法、界面缩放、清晰任务状态、低内存回退。
- P1：快捷键自定义、全键盘操作、屏幕阅读器标签、高对比度和减少动画。
- P0：日志不自动包含媒体正文或转录内容；本地功能无需强制账号、联网激活或云推理。

## 候选组件与本地可行性

### 语音识别

首选评估 [whisper.cpp](https://github.com/ggml-org/whisper.cpp) + multilingual small。C/C++、MIT，支持 Windows/macOS、CPU、Apple Metal、CUDA 和 Vulkan 路线。中文不可误用 .en 模型。较高配置可选 large-v3-turbo。官方列 small 约 466 MiB 磁盘与 852 MB 模型内存，large 约 2.9 GiB 与 3.9 GB；这些不是包含编辑器、缓存和媒体处理后的整机最低内存。模型越小通常越轻，但准确率须在目标素材上验证。

中文补充候选为 [SenseVoiceSmall](https://github.com/QwenAudio/SenseVoice) + [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)，用于中文、粤语、英文等对照测试；不能假设其输出直接具备完整词级字幕对齐。sherpa-onnx 程序为 Apache-2.0，模型逐个审核。

[faster-whisper](https://github.com/SYSTRAN/faster-whisper) / [CTranslate2](https://github.com/OpenNMT/CTranslate2)可做高吞吐备选，但 Python 与 GPU 库打包更复杂，Windows CUDA 方案不能直接当成 Mac 加速方案。

### 本地 TTS

基础路线为 sherpa-onnx + Kokoro 中英 ONNX。官方有中英多音色包及 int8 包；参见[包说明](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)及[Kokoro 权重模型卡](https://huggingface.co/hexgrad/Kokoro-82M)。模型卡标注 Apache-2.0；语音、字典、音素化工具和依赖须按实际交付包审计。支持语言不代表每个音色适合所有语言或任意混读，需听测。

更高质量可选 [CosyVoice2-0.5B](https://huggingface.co/FunAudioLLM/CosyVoice2-0.5B)，[代码仓库](https://github.com/QwenAudio/CosyVoice)与该权重卡均标 Apache-2.0。建议作为独立可选模块，先验证两平台安装、性能、内存和发音。上游首页包含更新模型描述，不能把 CosyVoice3 能力自动归给 2.0。不要在未实测前承诺 CPU 实时或任意 Mac GPU 支持。

### 对齐与翻译

[WhisperX](https://github.com/m-bain/whisperX)提供语言专属强制对齐及可选说话人分离，适合后续精准字幕路线。程序 BSD-2-Clause，语言对齐模型、说话人模型及访问条款独立审核。数字、重叠说话和说话人分离有已知限制，仍需人工校正入口。

[Argos Translate](https://github.com/argosopentech/argos-translate)支持离线语言包，程序 MIT/CC0。中文与英文双向先评估，语言包许可证单独确认；通过中间语言翻译会影响质量。

[libass](https://github.com/libass/libass)是 ISC 许可的 ASS/SSA 渲染器，适合字幕烧录；不代替编辑器字幕数据模型和 UI。

### 音频增强和视觉

- [RNNoise](https://github.com/xiph/rnnoise)：轻量本地降噪候选。
- [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet)：全带宽增强候选，代码 MIT/Apache 双许可；具体权重与包另验。
- [Demucs](https://github.com/facebookresearch/demucs)：人声/伴奏分离候选，原 Meta 仓库已归档，需明确维护和安全补丁责任。
- [SAM 2](https://github.com/facebookresearch/sam2)：交互式视频分割候选，官方代码和权重 Apache-2.0。分割掩码不等于发丝级 alpha，仍需细边缘与时间稳定处理；高性能依赖 GPU，平台移植必须实测。
- [OpenCV](https://github.com/opencv/opencv)：基础跟踪、光流、稳定等候选。

这些项目可本地运行不等于同时达到实时、4K 或同一显存要求。推理批次、视频分辨率、其他任务竞争和模型版本都会改变资源需求。

## 许可证与资产分发闸门

以下是基于上游声明的工程风险清单，不是法律许可保证。正式分发前审核代码、权重、依赖、数据/音色、字体、资产和编码器的具体固定版本。

- [F5-TTS](https://github.com/SWivid/F5-TTS)：代码 MIT，官方预训练权重 CC-BY-NC，不能直接作为商业产品默认权重。
- [Piper](https://github.com/OHF-Voice/piper1-gpl)当前引擎 GPL-3.0；[RVM](https://github.com/PeterL1n/RobustVideoMatting)代码 GPL-3.0。闭源方案须先处理许可义务或另获授权。
- Kokoro/sherpa 的实际包可能包含 [eSpeak-ng](https://github.com/espeak-ng/espeak-ng)组件或数据，需审核 GPL 义务及链接、分发结构；顶层 Apache 不代表整个安装包均为宽松许可。
- [FFmpeg 官方法律说明](https://ffmpeg.org/legal.html)：默认 LGPL，但编译选项、GPL 外部库和 nonfree 组件可改变分发条件；编解码专利另外评估。
- 建立软件与模型物料清单、NOTICE、来源链接、修改说明、必要源代码提供或替换机制；提交法律审核后再冻结发行配置。

## 素材与效果系统的离线替代

剪映热门歌曲、商业字体、IP 贴纸、商业模板、音色、数字人和在线素材库不能原样复制。会员可使用不等于在另一产品中拥有分发权。

设计原创或明确获分发授权的离线资源包。每个资源保存资产 ID、版本、作者、许可证、允许用途、必要署名、文件哈希、预览图和依赖。允许用户导入自有素材并本地搜索；不要将用户导入内容默认为可再分发。

效果/模板引擎需声明参数 schema、默认值、版本迁移、关键帧支持、所需字体和素材、渲染后端。优先实现可参数化的转场、花字和布局模板，而不是把少量静态预设误称为完整特效系统。加载不可信模板时不能执行任意远程脚本。

跨设备云草稿、在线授权素材搜索、直接发布社交平台等天然涉及网络服务。全离线替代是本地工程打包迁移、离线索引和导出文件；联网发布必须独立且可选，不属于离线核心。

生成视频、生成音乐、数字人/口型、复杂 AI 修复列为独立研究阶段。需逐项确认本地模型、质量、显存、平台及许可证，不能承诺和剪映云服务同款、同质量或同速度。

## 模型与资源包安装设计

1. 提供基础程序、可选语音/视觉/素材包，以及可用于完全断网机器的离线安装介质。
2. 每个包锁定模型、tokenizer、字典、音色、配置、运行库与许可证；附来源清单、SHA-256 和签名。
3. 用户可主动下载资源包或从本地导入。推理不依赖外网，不静默补下载，不在失败后转云推理。
4. 在执行前检查模型、内存和磁盘；缺包提示具体名称、大小和本地导入方法。
5. 模型任务在可取消的本地任务进程运行；限制线程/GPU/缓存，支持崩溃重启和安全清理。
6. 缓存按源文件指纹、时间范围、模型版本、音色和参数失效；保留导出可复现信息。
7. 禁用默认联网遥测与含内容的自动错误上传；离线许可证不能因断网失效。

## 建议实施阶段

- 第一阶段：在编辑与颜色核心稳定后，接入真正 ASR、可编辑字幕轨、SRT 导出和字幕烧录。
- 第二阶段：接入真实本地中英 TTS、固定授权音色、逐句生成、音轨编辑、时间冲突处理和导出闭环。
- 第三阶段：原创字幕样式、转场/贴纸/模板引擎、资源包管理、降噪与基础声音分离。
- 第四阶段：词级对齐、双语翻译、文本剪口播、跟踪抠像、多机位和高级 HDR。
- 后续独立阶段：高成本生成式 AI、超分/补帧、授权声音克隆和数字人。

每阶段先运行测试，再更新实现状态。不以按钮可点击、占位输出、模拟转录或仅有接口作为完成证据。

## 验收与功能矩阵

建议每条需求记录：ID、来源版本和平台、优先级、当前状态、对应代码、输入/输出范围、质量标准、测试证据、性能、许可证状态、剩余问题。状态使用“待确认”“计划”“实现中”“已集成未验收”“已验收”“不纳入”，不得将计划勾成完成。

### 离线端到端验收

- 断网冷启动，新建项目，导入本地素材，识别字幕，手动编辑，生成配音，加入效果并导出。
- 检查没有网络请求、隐式云回退、隐式模型下载或必须登录步骤。
- 重启并重新打开项目，时间戳、文字、音频、效果和资源链接可复现。
- 在无模型、损坏包、低磁盘、低内存和不支持 GPU 情况下给出可恢复提示。

### 质量与兼容测试集

- 中文、英文、中英混说、数字、人名、噪声和背景音乐、纯静音、重叠说话、长录音。
- VFR、不同采样率、长 GOP、旋转素材、横竖画幅、透明素材、丢失字体及离线资源。
- 至少覆盖 Windows CPU、计划支持的 Windows GPU、Apple Silicon 与计划支持的 Intel Mac；未支持的平台明确标识。
- 记录 CER/WER、字幕时间误差、人工纠错成本、TTS 发音与尾音完整性、配音时长冲突、峰值内存、耗时和导出同步。
- 为每个支持档位制定经实测的性能目标；不能从上游单一 benchmark 推导所有客户电脑的最低配置。

达到上述验收并有可检查结果后才可称为功能完成。本文件本身不证明任何功能已交付。
