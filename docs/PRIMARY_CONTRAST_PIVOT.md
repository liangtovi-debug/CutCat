# 基础调色：可调对比度中心

## 为什么先补这个缺口

对照 Blackmagic Design 的[官方调色面板说明](https://www.blackmagicdesign.com/products/davinciresolve/panels)（2026-10-23 查阅），Contrast 与 Pivot 是配套的基础调色控制：前者改变明暗差距，后者调整其影调中心。CutCat 此前虽有对比度，但只能围绕固定编码 RGB 0.5 拉伸。本轮把中心开放为明确有界的参数，比再增加一个限定器小按钮更直接改善整幅画面的基础调色。

这是工作流功能对照，不是算法复制。官方页面没有定义 Resolve 的完整内部数学，本实现不宣称数值对应、画面等效或达成专业色彩管理。现有“暖／冷”和“绿／洋红”仍是编码 RGB 偏移，不是色温／色适应白平衡，不能称为 Kelvin 白平衡。

## 使用

选中视频片段 → 色彩 → 基础。先调整对比度，再调整紧邻的“对比度中心”。两个工作区均保留此基础控制。中心 0–1，默认 0.500；键盘输入结束后提交，和其他基本参数一样产生可撤销编辑。未触碰的高精度项目值不会因界面只显示三位小数而被改写。

对比度为 1 时，中心单独改变不会影响画面；中心值仍保存，之后改变对比度时使用。重置颜色恢复中心 0.5。调色复制／粘贴携带中心，但仍保留目标输入编码解释；输入编码不属于创意调色复制的范围。

## 精确数值契约

参数 `contrast_pivot` 是有限实数（拒绝布尔），范围闭区间 `[0,1]`，不是线性亮度、18% 灰、IRE 标定或曝光档数。处理在编码 Rec.709 RGB 域，对每个颜色分量分别执行：

`output = (input - float32(pivot)) * float32(contrast) + float32(pivot)`

只在 `contrast != 1` 时执行。输入是线性曝光、RGB lift/gain/gamma 与重新编码、旧版编码增益之后的当前 RGB，不是原始素材值。默认 0.5 保留之前 float32 常数、运算次序和精度；对比度为 1 完全跳过新运算，避免无意义的舍入。

- 对比度为 0 时，所有有限 RGB 分量变为中心值。
- 输入等于中心时保持中心；浮点误差遵循上述 float32 算式。
- 对比度大于 1 时，低于中心的分量下降、高于中心的分量上升。
- 对比度为 1.5、输入 0.4 时，中心 0.5 得到约 0.35，中心 0.3 得到约 0.45。
- 仅参数中心有界。中间 RGB 可为负或大于 1，不在这里截断；这不会把 SDR 项目变成 HDR。
- 后续主/RGB 曲线沿用现有边界处理：恒等曲线完整绕过；非恒等分段曲线对定义域外输入按最外侧线段斜率延伸（不钳到端点）。限定器只接受有效范围内颜色；LUT 输入仍按其定义域限制，最终输出阶段才做对应截断／量化。

完整顺序不变：输入归一化／空间修复 → 线性曝光与 RGB 控制 → 709 编码 → 旧版增益 → 对比度及中心 → 饱和度／暖冷／色偏／阴影高光 → 主与 RGB 曲线 → 选择性色相曲线 → 联合限定器 → LUT → 输出转换。

取样器仍从指定的冻结源阶段读取 float32 RGB：色相曲线取样在选择性曲线前，限定器取样在限定器前。两者都包含基础对比度及中心的效果，不读取叠色或 8 位预览。修改中心会令旧源快照过期，必须重新取样；没有把窗口或修复运算重新排序。

## 工程格式与兼容

schema26 明确保存中心，缺少字段拒绝加载；schema1–25 不允许夹带该字段，缺失迁移为 0.5。字段追加于 Grade 末尾，旧位置参数构造保持含义。旧版本必须拒绝新版本工程，不以忽略字段的方式悄悄改变画面。

缓存指纹、恢复快照、事务历史、调色复制使用完整 Grade 数据，包含中心。默认值的兼容性使用未修改 v25 实际代码生成的黄金结果验证，而不是用新实现给自己生成期望值。

## 验收与仍存在的差距

验证包含独立标量数学、无截断中间值／曲线边界、历史默认逐位相同、工程版本与拒绝路径、恢复／复制／撤销／缓存、实际 RGB16 解码与预览／ProRes 422 HQ 10-bit 输出、冻结取样阶段以及中英文窄窗口／高 DPI Qt 操作。最终完整回归和解压验收数量见同轮验收说明；不能把开发中的局部测试当作最终通过。

这是 Linux 源码／离屏验证，未生成 Windows 或 macOS 原生安装包，未更新远程 main，未使用真实付费 API 或上传用户素材。预览仍有现有 8 位显示限制，ProRes 高位深路径的素材／叠加限制不变。

下一项有价值的基础调色缺口是受明确输入色域和参考白约束的真正白平衡／色适应（需要独立参考矩阵与色块验收），或跨片段参考静帧／匹配工作流。不能仅把现有暖冷滑块换成 Kelvin 标签就宣称补齐。HDR/OCIO、跟踪窗口和原生平台验收也仍未完成。
