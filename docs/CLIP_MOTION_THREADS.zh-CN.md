# 画面动画：有界滤镜线程，保持逐字节一致

本轮在上一轮表达式缓存上继续测量、优化、对照。只改变已验证的普通画面动画最终滤镜图调度，不重排表达式、几何、插值、alpha 或色彩数学；不降低 RGB16／10 位精度，不新增依赖、工程字段或 UI。schema32 不变。

## 明确限制

- 只有视频轨道含画面动画关键帧时才可能加速。按主机报告的逻辑 CPU 数选择已验证的 1、2 或 4 个滤镜线程，最多 4；不使用 auto 或全部核心。3 核主机选择 2。未知／单核选择 1。逻辑 CPU 数不是容器配额或实时可用资源的保证。
- 任意视频片段存在效果、动态限定器窗口，或工程含字幕／贴纸时，整个最终滤镜图明确保持 1 线程，包括当前禁用的项目。复杂组合仍走原路径，不以宽松容差换取加速；本轮没有宣称这些组合提速。
- 普通无动画／静态工程保持 1 线程。直接调用既有内部编译接口也默认 1；最终导出一次选定线程数，并把同一个数传给静态合成、动态合成行为探测与实际 FFmpeg 命令。
- 不在 RenderEngine 实例上存储可变线程选择，避免同时导出互相覆盖。上限是每次导出的滤镜调度器，不是整个 FFmpeg 的线程总数，更不是多个同时导出的总线程／内存配额。编码器、解码器、音频及已有缓存策略未改。
- 保留 blur 的 cpuflags=0 标量正确性保护。失败仍明确报错；没有静态首帧、低位深或有损精度回退。完全相同的输出不需要修改算法／预览缓存版本。

## 验证口径

先以独立随机 RGB16 和全码值范围下层直接对比 1↔2↔4 的原始 RGB16+alpha 与最终 8／10 位 YUV。覆盖切片首帧 N=0、短高度、隐藏键、保持／线性、32／128 键、旋转／镜像、透明外部和完全出界、不透明度 0。比较原始字节，不只比较编码图片或使用图像容差。

真实编号素材的完整图另测分数帧率、非零源起点、1/4／3/2／4 倍速、分割／左裁切、静态变换邻接片段和音频 PCM 的精确样本预算。测试检查能力探测与实际命令相同线程数，复杂效果＋窗口＋字幕＋贴纸仍为标量，保留 cpuflags=0；覆盖探测中取消、最终进程取消／超时、同一引擎并发导出不同线程策略与进程回收。完整旧节点保留、全量冻结回归和独立解压复测，以最终验收回执为准。

## 性能测量

见 [原始记录](CLIP_MOTION_THREADS_RAW.json)。所有主要计时在单一控制器中串行执行，1／2／4 三次重复，第二轮反序，1080p／4K、8／10 位分别测量。主机不是独占机器；不承诺用户设备有相同倍率。记录主机负载、CPU／墙钟时间、输出哈希及内存读数；cgroup CPU 配额不可见，明确记为未知。

scripts/benchmark_clip_motion_threads.py 测三帧 RGB16+alpha 阶段和最终 raw 合成，包括启动与 I/O，不含解码、调色、探测、音频或交付编码。每帧值只能是三帧总时间的摊销，不是播放 FPS。本轮没有独立分离完整滤镜初始化与稳态帧成本；原始日志保留 FFmpeg rtime 与外部墙钟时间，不能简单扣除启动后宣称稳态速度。FFmpeg 的 maxrss 可能包含启动前继承的父进程缓冲区，不能把其变化全部归因于滤镜线程。

scripts/benchmark_clip_motion_thread_exports.py 在每次新进程／新 RenderEngine 中测冷完整导出，包括能力探测、素材复核、RGB16 调色缓存、音频和实际 H.264／ProRes 编码；使用 64×48 FFV1 合成源缩放到 1080p／4K，三帧、1 fps；不是原生 1080p／4K 相机素材解码负载。合成素材创建／初始导入及结果解码哈希在计时外。输出解码像素、PCM 和编码文件都做跨线程哈希对照。整体子进程峰值内存包含调色、编码等所有阶段，不是单个滤镜的内存保证。AAC 解码可能包含编码器填充，精确项目音频长度另由未编码 PCM 样本预算测试覆盖。

两个脚本从源码根目录运行，使用 --output 指定尚不存在的目录。它们是 POSIX 实证脚本，不是 Windows／macOS 原生验收工具。原始计时的执行版本及完整日志另随本地证据保存，不能把后续包装改进当作重新跑过计时。

## 本机三轮中位数结果

三个合成帧，1→4 个滤镜线程，所有原始输出哈希一致：

- 1080p／8 位最终 raw：9.64 → 2.78 秒，3.47 倍。
- 1080p／10 位最终 raw：9.53 → 3.02 秒，3.15 倍。
- 4K／8 位最终 raw：38.37 → 9.80 秒，3.92 倍。
- 4K／10 位最终 raw：37.04 → 10.29 秒，3.60 倍。

包含缓存、探测、音频与交付编码的冷完整导出更接近实际等待，编码文件、解码像素和 PCM 哈希均一致：

- 1080p／8 位：11.18 → 4.64 秒，2.41 倍。
- 1080p／10 位：11.58 → 4.83 秒，2.40 倍。
- 4K／8 位：40.75 → 14.53 秒，2.80 倍。
- 4K／10 位：41.79 → 15.52 秒，2.69 倍。

完整导出观察到的整体子进程峰值约 397 MiB（1080p）及 1.39–1.43 GiB（4K），不是承诺的资源上限。部分成本不随合成线程数降低，因此不能把 raw 阶段倍率当成全工作流倍率。与上一轮只比较当前缓存算法的单线程基线；没有把不同轮次数字相乘宣称额外倍率。
